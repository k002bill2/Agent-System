| 2026-08-08 | **E-3(Codex 외부 검증) 옵션→기본 승격** + 무음 실패 구멍 차단. ① scope 하드코딩 제거 → **격리 트리 단일 scope 절차**: base에서 `git worktree add --detach` → 델타 패치만 `git apply`·커밋 → `--scope branch --base <base>` 1회. scope 분기·2회 실행·산출물 2개가 모두 사라진다. 근거: `working-tree`는 더티 전부를 보며 **필터를 받지 않아** "델타만 리뷰"를 현재 트리에서 지킬 수단이 없고, `branch`로 피하면 미커밋 기능 변경을 놓친다 ② **델타는 경로 뺄셈이 아니라 내용 diff** — `git diff --binary B0 B1`. 경로를 빼면 "Phase 1에 이미 더러웠던 파일을 이번 기능이 또 고친" 변경이 통째로 사라져 Codex가 base 버전을 보고 "이상 없음"을 반환한다. 스냅샷 `B0`/`B1`은 `git stash create`가 아니라 **임시 인덱스 + `write-tree`** — stash는 untracked 신규 파일을 트리에서 누락한다(실측). 격리 트리는 `<base>`가 아니라 **`B0`에서** 만든다 — 패치 preimage가 `B0`라 baseline·기능이 같은 hunk를 건드리면 `git apply`가 깨지는데, 하필 이 절차가 존재하는 이유인 더티 baseline 상황에서만 깨진다. `--binary` 없으면 바이너리 변경이 적용 불가 마커로만 나온다. **절차 전체를 격리 샌드박스에서 e2e 실측**(순수 baseline 제외 / 동시수정 파일은 기능 hunk만 / untracked·커밋분 포함 / apply 성공 / 리뷰 범위 일치) ③ Phase 1에 `00_base_ref.txt`(시작 HEAD·브랜치·B0) 기록 신설 — 셋 다 사후 복원 불가 ④ **E-3를 산출물 관문에 편입**(구성 표 E-3 행 + `E_codex_review.md`/`E3_SKIPPED.md` 실존이 Phase F 조건). 신선도 기준은 **델타 패치 해시**(`git diff --binary B0 B1 | shasum`, 기록·대조 양쪽 동일 형태) — 파일 목록·base SHA로는 부족하다(지적 반영 수정 후에도 둘 다 그대로라 수정 전 리포트가 통과). CRITICAL/HIGH 수정 후 E-3 재실행 필수. **같은 신선도 계약을 `E3_SKIPPED.md`에도 적용** — 보호를 성공 산출물에만 걸면 이전 런의 "델타 0건"/"CLI 미설치" 파일이 재개 런의 우회로가 된다 ⑤ 실행 스크립트 경로를 글롭이 아닌 **단일 경로로 확정**(`sort -V | tail -1`) — 캐시에 Codex 버전이 2개면 `*`가 다중 확장돼 node가 두 번째 경로를 서브커맨드로 읽고 즉시 종료, 산출물 없이 필수 Phase가 막힌다 ⑥ "지적 0건 ≠ 통과"(로그 3줄 이하 = 미실행, 델타 파일 수 ≠ 검토 파일 수 = 이식 누락) ⑦ 발사를 TaskStop과 같은 응답에서 금지.
