> `~/.claude/CLAUDE.md` 관리 블록에서 분리된 기록 (2026-08-15 컨텍스트 다이어트 — Agent-System `docs/context-engineering-2026-08.md` P1-2).

## 2026-08-15 — 컨텍스트 다이어트 (Claude 5 세대 규칙 적용)

Anthropic 공식 가이드(Thariq, "The new rules of context engineering for Claude 5 generation models", claude.com/blog, 2026-07-24)의 점진적 공개·중복 제거 원칙에 따라 관리 블록에서 개정 서사를 이 파일로 이전했다. 지침·함정(gotcha)은 블록에 유지.

**동시 발견·해소한 드리프트:** install.sh의 CLAUDEMD heredoc이 2026-08-09 정정 이전 상태로 스테일했다(아래 두 항목이 heredoc에 미반영 — "서브에이전트 200k" 옛 논거·STATE.md 분기·analyzer 미결 문구 잔존). 이 시점에 install.sh를 실행했다면 라이브 CLAUDE.md가 조용히 롤백됐을 것이다. 다이어트 블록을 양쪽에 동일 기록해 동기화했다. 메모리 `project_advisor_worker_bundle_heredoc_reversion`의 경고가 실제로 재현된 사례.

## 2026-08-09 — 실측 정정: "서브에이전트는 200k" 전제는 틀렸다

`mobile-ui-specialist`(`model: inherit`)와 같은 에이전트에 `model: "opus"` 를 명시한 경우 **양쪽 모두** 시스템 프롬프트가 `Opus 5 (1M context)` / `claude-opus-5[1m]` 로 보고했다. 즉 Agent 도구의 model enum 에 `[1m]` 표기가 없더라도 서브에이전트는 **부모의 1M 변형을 그대로 받는다**. (근거 수준 L2 — 모델 ID 문자열 관측이며 창 크기 직접 부하 측정은 아님. 다만 메인 세션이 자기 창을 판별하는 신호와 동일하다.)

**따라서 "위임하면 창이 좁아진다"는 위임 판단 절의 원래 논거는 성립하지 않는다.** 위임 상한은 창 손실이 아니라 **컨텍스트 재적재 비용과 정보 손실**(메인이 이미 읽은 것을 다시 읽음, 요약 과정의 유실)로 근거를 갈아끼웠다. 상한 항목 자체는 그 근거로도 여전히 유효하다.

같은 실측이 "토큰 무거운 작업" 절의 미결도 해소했다: `model: inherit` 은 `opus[1m]` 의 1M 창을 **상속한다**. 따라서 "티어만 올리고 창이 200k 그대로면 이득 0"이라는 analyzer haiku 유지 근거는 소멸했다 — analyzer 를 상속으로 올리면 Opus 5 를 1M 창째로 쓰게 되고, 남은 고려사항은 창이 아니라 **비용**뿐이다. 대량 입력을 굳이 넘길 이유가 없다는 본문 결론은 정보 손실 논거로 여전히 유효하다.

## 2026-08-09 — 컨텍스트 예산 상태 저장 분기 정정

분기 조건은 STATE.md 가 아니라 `.planning/phases/` 유무다. `/gsd:pause-work` 는 phases 구조를 탐지·기록·커밋할 뿐 STATE.md 를 읽지 않는다 — STATE.md 로 판단하면 phases 없는 레포에서 빈 손으로 phase 를 되묻는다.

## 2026-08-08 — 위임 판단 개정 (이전 "조언자 직접 코딩 금지"를 대체)

위임을 기본값에서 조건부 선택지로 전환했다. 모드 B에서 위임 상한을 적용하지 않는 이유: 상한은 *메인이 Opus 5* 라서 위임이 티어·창 양쪽에서 손해라는 전제 위에 있다. 메인이 Sonnet 이면 worker(Opus) 위임은 티어 상향이므로 전제가 뒤집힌다.

## 2026-08-08 — 컨텍스트 예산 티어 임계치 도출 근거

대형 창을 완화한 근거: Opus 5 는 1M 전 구간에서 instruction following·tool calling·reasoning 을 유지한다. 15/20% 를 그대로 적용하면 델타 200k 에서 정지해 남은 800k 를 쓰지 못했다. 반대로 40/55% 를 소형 창에 적용하면 200k 창에서 베이스라인 포함 창의 80% 까지 진행돼 'Context 75% Rule' 을 넘는다 — 그래서 하나의 비율이 아니라 티어로 나눈다.

이전의 고정 상수(51,133 / 59,000)는 200k 창 시절 값이라 1M 창에서 창의 6% 지점에 울렸고, 정상 작업 하나가 경고를 여러 번 띄워 규칙이 사문화될 위험이 있었다. 델타 기준이므로(0에서 시작) 창 사용률 임계치의 "턴 0 발동" 함정은 여전히 없다.

## 2026-08-08 — 리서치·외부 도구 완화 근거

원래 논거는 컨텍스트 보호였는데 1M 창에서 약해졌고, researcher 는 sonnet 이라 메인(Opus 5)보다 낮은 판단력으로 출처를 선별·요약한다 — 위임 자체가 정보 손실 지점이다. 서브에이전트가 이 도구들을 갖는 것은 여전히 모순이 아니다 — 컨텍스트가 분리되기 때문이다.

## 2026-08-08 — 상향 경로 Fable 5 신설

명시적 opt-in 전용으로 신설. 단가가 Opus 5 의 2배($10/$50 per 1M)라 자동 승격은 두지 않는다.

## 2026-08-08 — 토큰 무거운 작업 개정

"코드베이스 분석·긴 로그·대량 요약은 analyzer 에 먼저 위임한다"는 의무를 폐기했다 — analyzer 는 당시 200k(Haiku 4.5) 인식이라 1M 메인이 대량 입력을 넘기는 것은 구조적 역전이고, 요약 과정에서 정보가 손실된다. (창 전제는 2026-08-09 정정으로 수정됐으나 정보 손실 논거는 유지.)
